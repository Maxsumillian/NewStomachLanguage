OVERVIEW
--------
StomachLang is a C++-based system with custom types and a CPU-driven execution model.

- Edible   -> Boolean
- Calories -> Integer
- Foods    -> String

All types behave like objects, but ALL expression evaluation is handled by the CPU runtime (StomachLang::cpu).


1. VARIABLES
------------

BOOLEAN (Edible)
----------------
Edible coffee;
coffee = true;

Edible plane = false;
Edible car(false);


INTEGER (Calories)
------------------
Calories applePie = 580;

Calories milkShake;
milkShake = 300;

Calories cake(800);


STRING (Foods)
--------------
Foods apple = "apple";

Foods pie;
pie = "pie";

Foods honey("honey");


2. ARITHMETIC (Calories)
------------------------
Calories a = 100;
Calories b = 50;

a + b;
a - b;
a * b;
a / b;
a % b;

Mixed:
Calories peachPie = applePie + milkShake;
Calories complex = applePie + 123 + milkShake + 321;


3. STRINGS (Foods)
------------------
Foods combo = "eating pie" + " its good " + pie;

Rules:
- Foods + Foods -> concatenation
- Foods + string literal -> concatenation
- Foods + INT -> handled by CPU rules (ignored or converted depending on CPU config)


4. BOOLEAN (Edible)

if (isTrue == true) {}

6. MIXED EXPRESSIONS (IMPORTANT SYSTEM RULE)
--------------------------------------------

StomachLang supports mixed expressions between literals and variables.

CORE RULE:
All expressions are evaluated through the CPU:

StomachLang::cpu is responsible for ALL computation logic.

Operators (+ - * / % == > <) do NOT perform computation directly.
They only:
- forward operands to CPU
- trigger CPU execution
- return CPU accumulator result

--------------------------------------------

CALORIES (Integer Expressions)
------------------------------
Rules:
- All values are treated as INT internally
- CPU evaluates expressions step-by-step
- Left-to-right evaluation unless overridden by CPU precedence rules

Example:
Calories result = applePie + 123 + milkShake + 321;

Execution order:
((applePie + 123) + milkShake) + 321

--------------------------------------------

FOODS (String Expressions)
--------------------------
Rules:
- Foods are concatenated using CPU string accumulator
- String literals are merged seamlessly
- Non-string values are handled via CPU conversion rules (if enabled)

Example:
Foods combo = apple + pie + " dessert";

Execution:
(("apple" + "pie") + " dessert")

--------------------------------------------

MIXED TYPE RULE (STRICT)
------------------------
StomachLang does NOT allow implicit cross-type operations unless explicitly supported by CPU.

Invalid:
Calories + Foods
Edible + Calories
Foods + Edible

All cross-type behavior must be defined in CPU conversion logic.


7. CPU IS THE SOURCE OF TRUTH
-----------------------------
Important architecture rule:

- Operator overloads = syntax layer
- CPU = execution layer
- CPU accumulator = final result holder

No expression is complete until processed by:
StomachLang::cpu
